# 开跑记录与挑战跨端 v0.1

这一版把[开跑记录与成长同步](10-开跑记录与成长同步-v0.1.md)里最后一块“只在本机”的数据接上：手机端保存的跑步记录会写进共享 Mock API，社团后台的“记录与导出”看到同一批记录；后台创建的挑战也会出现在手机成长页和挑战页，并按同一条规则计算个人进度。

- 日期：2026-11-23
- 范围：`mock-api/` 跑步记录与挑战接口、`mobile/` 开跑 / 成长 / 挑战 / 消息、`admin/` 记录与挑战页
- 数据：跑步记录和挑战都在本地 Mock API 进程内存
- 状态：可点击原型，未接真实账号、真实 GPS 轨迹或数据库

## 1. 这一版解决什么

在公告和邀请码跨端之后，跑步记录和挑战仍然是断的：

- 手机端跑步记录只存在 `RunContext` 的内存里，刷新页面就回到种子；后台完全看不到成员新跑的距离。
- 社团后台的“记录与导出”读前端 repository 里的 25 条示例记录，和手机端保存的记录是两份账。
- 后台“挑战”页也读本地示例数据，新建、结束只影响这一页；手机成长页没有挑战卡，也没有挑战列表。
- 挑战本该由团长发起、成员在手机上看进度，但两端没有共享状态，也没有任何通知。

这一版做四件事：

1. Mock API 新增 25 条跑步记录、3 个挑战种子，以及 `/api/runs`、`/api/challenges` 接口。
2. 手机端保存记录时先本地乐观更新，再 `POST /api/runs`，成功后用服务端记录替换；失败保留本地记录并提示未同步。
3. 后台记录页、挑战页改接共享接口；创建挑战后写入 API，结束挑战用 `PATCH` 写 `endedAt`。
4. 创建挑战时给所有在团成员写一条 `challenge` 站内消息；手机消息中心可点进挑战页，未读数同步下降。

仍然不做：真实 GPS 轨迹上传、记录编辑/删除、挑战报名与退出、私密记录开关、排名、分页、真实账号和数据库。

## 2. 数据模型

跑步记录存在 `state.runs` 里：

```ts
type RunSource = 'gps' | 'screenshot' | 'file' | 'manual';

interface Run {
  id: string;          // run-001 / run-<timestamp>-<rand>
  memberId: string;    // m-001
  memberName: string;
  date: string;        // YYYY-MM-DD，不能晚于今天
  title: string;       // 手动补记时取备注，否则取跑步类型
  distanceKm: number;  // 保留 1 位小数
  durationMin: number; // 保留 1 位小数
  note: string;        // 选填，最多 200 字
  source: RunSource;
  visibility: 'club';  // v0.1 固定社团可见
  createdAt: string;
  pace?: string;       // 接口计算，如 6'01"
}
```

挑战存在 `state.challenges` 里：

```ts
type ChallengeStatus = 'upcoming' | 'active' | 'ended';

interface Challenge {
  id: string;          // chl-001 / chl-<timestamp>
  title: string;
  description: string;
  targetKm: number;    // 1–1000
  startDate: string;   // YYYY-MM-DD
  endDate: string;     // YYYY-MM-DD
  createdAt: string;
  endedAt?: string;    // 团长手动结束后写入
}
```

状态按下面的顺序计算，先命中先返回：

| 优先级 | 条件 | 状态 | 手机端文案 |
| --- | --- | --- | --- |
| 1 | `endedAt` 存在 | `ended` 已结束 | 已结束 · 进度只读 |
| 2 | 今天晚于 `endDate` | `ended` 已结束 | 已结束 · 进度只读 |
| 3 | 今天早于 `startDate` | `upcoming` 未开始 | X 月 X 日 开始 |
| 4 | 以上都不满足 | `active` 进行中 | 还剩 N 天 |

派生字段由接口按请求里的 `memberId` 计算：

- `participantCount`：当前 `status === 'active'` 的成员数，种子为 8。
- `completedCount`：个人累计里程达到 `targetKm` 的成员数。
- `clubProgressKm`：所有在团成员个人里程的平均值，保留 1 位小数。
- `myKm` / `myPercent` / `myCompleted`：仅当请求带 `memberId`。
- `daysLeft`：仅进行中的挑战，按结束日 23:59:59 向上取整，最少为 0。
- `startAt` / `endAt`：给前端展示的 `+08:00` 时间边界。

个人里程只统计同时满足以下条件的记录：

- 属于该成员；
- `date` 在挑战起止日期内；
- `visibility !== 'private'`；
- 挑战已手动结束时，`createdAt <= endedAt`，结束后的补录不再计入。

## 3. 种子数据

跑步记录种子共 25 条，覆盖 8 名在团成员（m-001、m-005 至 m-011）：

- 日期以本周为锚点，分布在今天、本周早些时候和前三周。
- 来源覆盖 GPS、截图、文件、手动四种。
- 合计 172.4 km；m-001 有 7 条，本周 18.6 km、本月 50.5 km。
- 林小满（m-001）是手机端演示账号，后台按成员筛选时正好 7 条。

挑战种子 3 个，按当前月份动态生成：

| id | 标题 | 目标 | 日期 | 状态 |
| --- | --- | --- | --- | --- |
| chl-001 | 本月 · 80 公里挑战 | 80 km | 本月 1 日 — 本月最后一天 | 进行中 |
| chl-002 | 下月 · 60 公里挑战 | 60 km | 下月 1 日 — 下月最后一天 | 未开始 |
| chl-003 | 上月 · 60 公里挑战 | 60 km | 上月 1 日 — 上月最后一天 | 已结束 |

m-001 在 chl-001 的初始进度是 50.5 / 80 km、63%、还剩 8 天；8 人参与、0 人完成。

## 4. 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/runs?memberId=m-001` | 记录列表，按日期、创建时间倒序；带 `memberId` 只看本人 |
| POST | `/api/runs` | 新增记录，返回带 `pace` 的记录 |
| GET | `/api/challenges?memberId=m-001` | 挑战列表，按进行中、未开始、已结束排序；带 `memberId` 返回个人进度 |
| POST | `/api/challenges` | 新建挑战，并给在团成员写站内消息 |
| PATCH | `/api/challenges/:id` | 只允许 `{ "status": "ended" }`，写入 `endedAt` |

新增记录校验：

- `memberId` 必须存在，否则 404。
- `distanceKm` 需在 0.1–100 之间，服务端保留 1 位小数。
- `durationMin` 需在 1–1440 之间。
- `date` 必须是 `YYYY-MM-DD`，且不能晚于今天；缺省为今天。
- `source` 只接受四种来源，否则回退为 `manual`。
- `title` 截到 40 字，`note` 截到 200 字；空标题写“跑步记录”。

新建挑战校验：

- 标题 2–60 字，说明 5–300 字。
- 个人目标 1–1000 km。
- 起止日期必须是 `YYYY-MM-DD`，结束日期不能早于开始日期。
- 创建成功后立即给所有 `status === 'active'` 的成员写一条消息，标题“跑团挑战：<标题>”，正文包含起止日期、个人目标和“只累计社团可见的跑步记录，不做排名”。
- 未开始的挑战也会通知，方便成员提前知道；目前没有“撤销通知”。

结束挑战：

- 只有 `status` 为 `ended` 的请求体被接受。
- 已经结束的挑战再次结束会返回“这个挑战已经结束了”。
- 结束后不删除记录、不撤回站内消息；个人进度变为只读，结束时间之后的补录不计入。

## 5. 手机端

### 5.1 开跑与记录

- `RunContext` 先用本地种子渲染，挂载后拉 `GET /api/runs?memberId=m-001`；成功后整体替换为服务端记录。
- `addRun` 先插入本地记录，让首页本周/本月、最近记录、成长页立即变化；同时 `POST /api/runs`，成功后用服务端返回替换同一条记录，失败保留本地记录并显示“这条记录还没同步到后台”。
- 手动补记、计时结束补距离、截图确认、文件导入最终都走同一个 `addRun`。
- 手动补记成功后提示“已记录 X km，首页和成长档案已同步。”；输入区清空。

### 5.2 成长页

- “活动参与”卡之后新增“跑团挑战”区，右上角“全部挑战”进入 `/challenges`。
- 优先显示进行中的挑战，没有进行中才显示未开始；都没有时显示空态。
- 卡片显示标题、状态 Pill、`myKm / targetKm`、百分比或“已完成”、进度条、剩余天数或日期范围、参与人数 / 完成人数。
- 说明文字固定为“只累计社团可见的跑步记录；活动出勤不重复计入，私密记录不计入。”
- 页面获得焦点时刷新挑战，新记录保存后切回成长页能看到 `myKm` 和百分比变化。

### 5.3 挑战页

- `/challenges` 展示全部挑战，按进行中、未开始、已结束排序。
- 进行中：剩余天数、参与人数、完成人数。
- 未开始：开始日期、“开始后自动累计社团可见记录”。
- 已结束：日期范围、“已结束 · 进度只读”，卡片降低透明度。
- 底部说明结束后进度只读、补录不再计入；页面获得焦点时刷新。

### 5.4 消息中心

- 新增 `challenge` 消息类型，行内图标“挑”、标签“跑团挑战”。
- 消息带 `challengeId`，点击后先标已读，再跳 `/challenges`；链接文案“查看挑战进度 ›”。
- 消息中心副标题补充“跑团公告和挑战”。
- “我的”页重置演示数据时一并刷新挑战，提示“活动演示数据、消息和挑战已重置，后台和手机端都回到初始状态。”

## 6. 社团后台

### 6.1 记录与导出

- `recordsApi.listRecords()` 调 `GET /api/runs`，不再用本地 repository。
- 统计卡显示当前记录数、合计里程、参与成员数；种子为 25 条 / 172.4 km / 8 人。
- 表格显示日期、成员、标题、距离、时长、配速、备注、来源；配速由接口计算。
- 按成员或备注搜索，林小满筛出 7 条；清除筛选回到 25 条。
- “导出 CSV”仍在前端把当前筛选结果转成 CSV，不额外调接口。
- 记录页没有分页和自动刷新，新增记录后重新进入或刷新页面可见。

### 6.2 挑战

- `challengeApi` 提供列表、创建、结束三个方法；页面不再用本地 repository。
- 统计卡：进行中、未开始、进行中挑战的参与人次；种子为 1 / 1 / 8。
- 新建挑战弹窗默认开始日期为明天、结束日期为 31 天后、目标 60 km；可改成今天，创建后立即是进行中。
- 创建成功 toast “新的挑战已创建。”，列表重新拉取；结束成功 toast “挑战已结束，记录进入只读。”
- 卡片显示状态、日期范围、社团平均进度、参加人数、完成人数和个人目标。
- 只有进行中的挑战有“结束挑战”按钮，确认后调 `PATCH`；已结束卡片显示“已结束，进度只读”，未开始显示“开始后自动累计社团可见记录”。
- 挑战页没有自动刷新；手机端新建记录后，后台需要刷新才能看到平均进度变化。

## 9. 边界与下一步

- 跑步记录只存在 Mock API 进程内存，重启或重置回种子，不落数据库。
- GPS 仍只在前台算距离，不保存轨迹、不上传地图；计时结束后若没有有效 GPS 距离，需要手动补。
- 记录不能编辑或删除；后台只能查看和导出，不能更正。
- `visibility` 固定为 `club`，手机端没有私密记录开关；挑战只累计社团可见记录这条规则暂时只是数据模型预留。
- 挑战没有报名/退出，所有在团成员自动参与；参与人数固定为在团人数。
- 创建挑战就给所有在团成员发消息，未开始也发；结束挑战不撤回消息，也不通知“挑战已结束”。
- 不做排名、不做配速比较；后台只显示社团平均进度和个人目标。
- 记录和挑战接口都没有分页、搜索参数或自动刷新；后台搜索和 CSV 导出在前端完成。
- 下一步可以做：记录详情与删除、后台更正记录、挑战报名与退出、结束挑战通知、挑战进度自动刷新、真实设备 GPS 与轨迹隐私评估。
