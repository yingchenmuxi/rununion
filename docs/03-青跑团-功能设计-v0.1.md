## 0. 本版已定

- 目标用户默认 **14 岁以上**，不做 14 岁以下注册。
- 第一版主线：**A. 社团运营**。
- **排名体系后置**，第一版不做公开榜单。
- **线下活动后置**，第一版不组织线下约跑/比赛。
- 开发环境：Windows 本地优先，后续迁服务器。
- 社团自管：社长审批成员、发公告、发起线上挑战；**社团由平台管理员开通**，**不设老师审批角色**，平台只做审核和兜底。
- 不做身份证实名；数据最小化。
- 14–17 岁仍按未成年人处理：第一版只在社团内部线上使用，V0.1 不收集家长回执；涉及线下活动或公开榜单时，再升级为必填的监护人同意（见第 10 节第 5 条）。

## 1. 第一版目标

先让一个真实社团跑起来，而不是先做全国平台。

试点假设：

- 1 个社团
- 30–50 名成员
- 连续使用 4 周

观察指标：

- 邀请码加入完成率 ≥ 60%
- 完成首次跑步记录 ≥ 70%
- 每周至少记录 1 次的比例 ≥ 50%
- 4 周后仍在使用 ≥ 40%
- 社团管理员每周后台操作 ≤ 30 分钟
- 0 起严重隐私/安全事故

## 2. 角色

| 角色 | 能做什么 | 不做什么 |
|---|---|---|
| 跑者 | 加入社团、记录跑步、看自己的成长、看社团公告/挑战 | 不能看别人的私密记录，不能管理社团 |
| 社长（owner） | 生成邀请码、审批成员、发公告、发起线上挑战、查看社团汇总、导出数据 | 不能创建社团（V0.1 由平台管理员开通），不能修改别人的跑步记录，不能查看成员私密记录；V0.1 不设多管理员/角色转移 |
| 平台管理员 | 开通/审核社团、指定社长、重置社长密码、处理举报、停用违规账号、查看平台审计 | 不参与社团日常运营，不查看成员私密记录 |
| 家长/监护人 | V0.1 不是 App 账号，也不收集回执；做线下活动/公开榜单前再补监护人同意 | 不需要安装 App，不需要每天登录 |
| 学校/老师 | 不是必须角色 | 产品不依赖老师审批 |

## 3. 核心流程

成员端：

```
打开 App
  → 输入邀请码
  → 设置昵称/密码
  → 填写年龄段、城市、跑步目标
  → 同意用户协议/隐私政策
  → 提交加入申请
  → 管理员审批通过
  → 首页
  → 记录一次跑步（计时或手动）
  → 社团主页/个人成长
  → 查看公告或参加线上挑战
```

管理员端：

```
Web 后台登录
  → 创建/进入社团
  → 生成邀请码
  → 审批成员
  → 查看成员列表和社团汇总
  → 发公告/发起线上挑战
  → 导出数据
```

## 4. 页面清单

成员端（移动端）：

1. 登录/邀请码页
2. 完善资料页
3. 首页：本周跑量、目标进度、社团动态、公告
4. 跑团页：社团信息、成员、公告、线上挑战
5. 开跑页：计时器、手动记录、跑步感受
6. 成长页：个人周/月跑量、连续记录、个人最好成绩（先不做排名）
7. 我的页：资料、隐私设置、退出社团、删除账号
8. 公告/挑战详情页

管理端（Web）：

1. 管理员登录
2. 社团概览
3. 成员审批/成员列表
4. 邀请码管理
5. 跑步记录查看
6. 公告/线上挑战管理
7. 数据导出
8. 审计日志（先只读）

## 5. 功能范围

### V0.1 要做

- 社团创建与平台审核
- 邀请码加入、管理员审批
- 成员资料（昵称、年龄段、城市/区、性别可选、每周目标）
- 跑步记录：计时器 + 手动填写距离/时长/感受；不采集 GPS
- 社团主页：成员、社团周跑量、公告
- 个人成长：周/月跑量、连续记录、个人最好成绩（手动录入）
- 社团汇总：总跑量、参与人数、人均跑量（只展示，不排名）
- 公告
- 线上挑战：例如“本周完成 3 次跑步”，只做打卡，不做线下约跑
- 管理后台：审批、邀请码、记录查看、公告/挑战、导出
- 同意管理：用户协议/隐私政策弹窗；V0.1 不收集家长回执；做线下活动/公开榜单前再补监护人同意流程
- 隐私：默认社团内可见；单条记录可设为私密；退出社团；删除账号
- 数据导出：管理员导出社团成员和跑量 CSV；成员导出自己的记录

### V0.2 以后

- 线下活动发布/报名/签到/安全清单
- 成长榜/成绩榜（区/市/省/全国）
- 经验库（人工精选 → 投稿审核 → AI 检索）
- 同城/同水平跑友匹配
- 公益助跑（先物资/名额，后基金会合作）
- 金字传驿接力
- GPS 轨迹、原生 iOS、支付

### V0.1 明确不做

- 公开个人速度榜
- 陌生人私信
- 精确位置/实时定位
- 现金募集/支付
- AI 问答
- 线下活动组织
- 身份证/人脸识别

## 7. 权限与隐私

- 默认：个人资料和跑步记录仅本社团成员可见。
- 单条跑步记录可设为“仅自己可见”。
- 不展示真实姓名、手机号、家庭住址、学校班级、精确位置。
- V0.1 不收集家长回执；以后如启用，管理员只能看到“已交/未交”，看不到回执内容。
- 成员退出社团后，历史记录默认保留在个人账户，社团汇总中匿名化。
- 成员可导出自己的数据、删除账号；删除后 7 天内可撤回，之后不可恢复。
- 管理后台所有审批、导出、删除操作写审计日志。
- 不在公开网页索引成员资料；不做公开分享链接（V0.1）。

## 8. 管理后台

第一版建议做 **Web 后台**，手机端只给成员用。

原因：社长审批成员、导出表格、发公告，在电脑上更快；也避免在手机端做一套复杂的权限界面。

后台入口先只给社团管理员，平台管理员用单独账号。后续再考虑小程序/手机管理。

## 9. 技术备注

- 移动端继续用 Expo/React Native；Web 后台可以先用同一套 Expo Web 或独立简单页面。
- 本地开发先用示例数据；接真实数据前，先在 Windows 本地跑 PocketBase（自带数据库、后台、文件存储）。
- 上线前再做 HTTPS、备份、权限、日志、隐私政策和 APP 备案。
- 真实未成年人数据不放在公网测试端口；测试用假数据。
