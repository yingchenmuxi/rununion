## 1. 本轮决策

| # | 你的选择 | 我的解读 | 对项目的影响 |
|---|---|---|---|
| 1 | 全国 | 产品全国可用；运营按密度推进 | 数据模型从第一天支持城市/学校；不全国同步投放 |
| 2 | 安卓 App，苹果网页 | 一套 Expo 代码，Android APK + iOS/桌面 PWA | 避开苹果开发者年费；网页功能要能降级 |
| 3 | token 随便用，其他无预算 | 研发零现金启动；AI 额度可用 | 先用免费额度；全国公开上线的硬成本后置 |
| 4 | 学校 | 学校跑团作为冷启动供给 | 新增学校/教师/班级邀请码/监护人同意流程 |

## 2. 四个坚持，一个修正

### 2.1 全国：全国架构，密度运营

- 全国注册、全国学校/跑团地图、全国成长总量，从第一天就可以有。
- 但首页内容按城市/学校聚合；没有供给的城市显示“正在招募种子学校”，不显示空榜单。
- 运营节奏：1 所学校 → 1 个区 → 1 座城市 → 1 个省 → 全国连线。
- “全国”是数据架构和品牌叙事，不是第一天的地推范围。

### 2.2 平台：Android App + 苹果 Web

- 一套 Expo（React Native）+ Expo Router 代码：
  - Android：原生 APK，直接下载安装。
  - iOS/桌面：Expo Web 导出为响应式网页，Safari 可“添加到主屏幕”，形成 PWA。
- 好处：不需要苹果开发者账号（省 99 美元/年），不需要上架 App Store；Android 也可以先直接发 APK。
- 代价：iOS 网页不能做后台 GPS、原生推送受限、部分健康数据接不了；第一版核心功能必须不依赖这些。
- 安卓应用商店上架、软著、备案放到试点之后。

### 2.3 预算：零现金启动，明确边界

现在就能零现金做：

- 代码与版本管理：GitHub 免费私有仓库。
- 开发调试：Expo Go 免费；Android 真机调试。
- 后端：Supabase 免费额度（Postgres、Auth、Storage）。
- 网页托管：Cloudflare Pages / Vercel / Netlify 免费额度。
- Android APK：EAS Build 免费额度或本地 Gradle 构建。
- 设计素材：开源图标/字体；先不买图库。

零预算做不到的（全国公开上线前必须解决）：

- 境内服务器 + ICP/APP 备案。
- 短信验证码（按条计费）。
- 安卓应用商店上架（软著、隐私检测、渠道费用）。
- 线下活动保险、急救、场地。
- 法务/隐私政策/未成年人保护规则的专业审核。
- 结论：零预算可以做到“原型 + 一所学校试点”；全国公开运营不是零预算能完成的。

AI token：

- 如果指模型 API 额度：第二版接 AI 检索/问答，服务端代理，保护 key。
- 如果只是当前对话的 token：AI 功能需要另配 API key，不阻塞第一版。
- 第一版先用“人工精选 + 教练问答”，避免医疗风险和 token 成本。

### 2.4 学校：最好的冷启动，也是最保守的客户

- 学校能提供：真实用户、固定场景、老师背书、家长信任、活动场地。
- 学校会问：数据放哪？家长同意吗？出事谁负责？有没有备案？
- 所以合规不是拖累，是进学校的门票。
- 产品上新增“学校跑团”：
  - 体育老师/教练申请开团，平台人工审核。
  - 学生用班级邀请码/二维码加入。
  - 监护人签署同意书（学校可批量组织）。
  - 学校后台只看聚合数据（参与率、总里程、进步），不看个人隐私。
  - 校际“成长联赛”：比参与、比坚持、比进步，不只比速度。

### 2.5 未成年人：不做“零限制”，做“风险分层”

我同意你的目标：不能把未成年人当犯人，不能做一个处处要家长扫码的“儿童版”。过度限制会把核心用户赶走。

但“零限制”不是产品选择，是法律和生存底线：

- 不满 14 周岁的个人信息属于敏感个人信息，处理须监护人同意并制定专门规则（《个人信息保护法》）。
- 《未成年人网络保护条例》对内容、沉迷、隐私、网络欺凌有明确要求。
- 公开募捐需要资质（《慈善法》）；个人/普通公司不能向公众收钱。
- APP 备案/ICP、应用商店审核、学校合作都会查这些。
- 一次未成年人安全事故或隐私泄露，足以让产品下架、被罚款、被学校拒绝。

所以方案是：**功能保留，风险分层，默认安全。**

| 你想保留的功能 | 零限制的风险 | 我们的做法（不砍功能） |
|---|---|---|
| 社交/私信 | 陌生人骚扰、约见 | 不做全站陌生人私信；做认证跑团群、活动群、教练问答；群有管理员；未成年人默认只在团内互动；举报/禁言/踢人 |
| 排行榜 | 过度训练、焦虑、作弊 | 个人榜默认私密，可自愿公开；学校/团队榜看参与、坚持、进步；成绩分“手动/活动/赛事”三级；年龄分组；不设大额现金奖 |
| 同城匹配 | 精确位置泄露、陌生人约见 | 只到城市/区；推荐跑团和活动，不做 1 对 1 陌生人；线下在公开场所、有组织者、有保险；报名后可见集合点 |
| 位置 | 家庭/学校位置泄露 | 不采集后台精确位置；跑步记录手动/前台计时；不做“附近的人”；活动地点由组织者公开 |
| 公益 | 非法募捐、诈骗 | 不直接收现金；与有公募资格的基金会合作；物资/名额/教练时间；公示 |
| 内容/AI | 不良信息、医疗误导 | 先审后发/举报下架；医疗免责声明；AI 引用来源、不诊断；教练认证 |
| 注册/使用 | 门槛高、用户流失 | 不要求所有功能实名；年龄 + 监护人同意；学校邀请码批量导入；只有高风险动作才二次确认 |

年龄分层建议：

| 年龄段 | 账号 | 社交 | 公开资料 | 位置 | 高风险动作 |
|---|---|---|---|---|---|
| 10–13 | 监护人同意 + 专门规则 | 仅认证跑团/班级群 | 默认不公开 | 仅城市/区 | 监护人确认 |
| 14–17 | 监护人同意 + 平台规则 | 团内/活动群；不开陌生人私信 | 可选公开，需确认 | 仅城市/区 | 二次确认/监护人确认 |
| 18–20 | 自主注册 | 完整社区功能 | 自主选择 | 自主选择 | 常规确认 |

这不是“过多限制”，是“让功能能长期存在”。一个被下架、被家长举报、出一次事故的 App，才是对用户最大的限制。

## 3. 修正后的 MVP

供给从“泛跑团”改成“学校跑团 + 社区跑团”双入口，第一版主推学校。

做：

1. 学校/跑团入驻与审核（教师/负责人认证、学校主页）。
2. 学生加入（班级邀请码/二维码、监护人同意、年龄分层）。
3. 活动发布与报名（校内约跑/校际活动、风险告知）。
4. 跑步记录（手动 + 计时；GPS 第二版）。
5. 成长档案（PB、月跑量、连续周数、徽章）。
6. 学校/团队成长榜（参与、总里程、进步；个人可选公开）。
7. 经验库（20–30 篇精选 + 教练问答，人工审核）。
8. 安全中心（隐私、举报、拉黑、监护人控制）。
9. 管理后台（学校/跑团审核、内容审核、举报处理）。

不做（第一版）：

- 全国个人速度总榜
- AI 问答
- 1 对 1 陌生人匹配/私信
- 现金捐赠
- 跨省接力
- 实时 GPS 轨迹
- 公开社交动态
- 付费会员

试点：1 所学校，100–300 名学生，4 周，1 场校内活动。

## 4. 技术架构

- 客户端：Expo（React Native）+ TypeScript + Expo Router。
- 目标：
  - Android：原生 APK。
  - iOS/桌面：Web 导出 + PWA manifest，Safari 添加到主屏幕。
- 后端：Supabase（Postgres + Auth + Storage + Row Level Security）。
- 网页托管：Cloudflare Pages（免费）。
- 构建：Expo Go 开发；EAS Build 免费额度或本地 Gradle 出 APK。
- 登录：试点用“学校邀请码 + 邮箱/用户名”，避免短信费用；全国版再补手机号/微信登录。
- AI：第二版，Supabase Edge Function 代理模型 API；pgvector 做检索；不直接给诊断。
- 地图：第一版只存城市/区/活动地点文本；第二版接高德/腾讯位置服务。
- 推送：第一版站内通知；第二版 Android 推送 + iOS Web Push（有限支持）。
- 管理后台：第一版 Supabase 控制台 + 简单网页；第二版独立后台。
