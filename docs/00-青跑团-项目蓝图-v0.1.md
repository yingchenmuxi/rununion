> 实现状态（2026-11-19）：跑步记录已实现 GPS / 截图确认 / 文件导入三通道，见 [开跑记录与成长同步 v0.2](10-开跑记录与成长同步-v0.1.md)；知识库第一版已完成 9 篇本地文章、搜索、筛选、收藏和关联阅读，见 [手机端跑步知识库 v0.1](11-手机端跑步知识库-v0.1.md)；本文保留当时的规划口径。

> 状态：草案（待创始人拍板）
> 日期：2026-11-15
> 一句话：让每一个想跑下去的青少年，都能找到同伴、方法和舞台。

## 0. 先给结论

青跑团不是“再做一个跑步 App”，而是一个以跑团为节点、以成长记录为底座、以公益为底色的青少年长跑共同体。

六个功能不能同时上线。第一版只做三件事：**跑团愿意入驻、青少年愿意记录、家长愿意放心**。其他功能都建立在这三件事之上。

## 1. 用户与角色

| 角色 | 他们是谁 | 他们真正要什么 | 第一版是否需要 |
|---|---|---|---|
| 青少年跑者 | 10–20 岁，刚开始跑或已在校队/跑团 | 被看见、有同伴、别受伤、能坚持 | 是 |
| 家长/监护人 | 孩子的安全与时间守门人 | 安全、透明、不耽误学习 | 是（同意与查看） |
| 跑团组织者 | 民间跑团、学校社团、社区跑团 | 招人、管活动、留人、被认可 | 是 |
| 教练 | 体育老师、田径教练、资深跑者 | 输出经验、获得尊重 | 第二版 |
| 学校/社区 | 场地、生源、背书 | 安全、成果、品牌 | 第二版 |
| 公益伙伴 | 基金会、慈善组织、企业 | 合规、透明、真实故事 | 第三版 |
| 平台管理员 | 你和早期团队 | 审核、风控、运营 | 是 |

## 2. 要解决的真问题

1. **不会跑**：初跑者缺科学方法，容易受伤、放弃。
2. **没人陪**：长跑孤独，青少年尤其需要同伴和正向压力。
3. **跑团散**：各地跑团各自摸索，缺工具、缺连接、缺资源。
4. **没记录**：孩子的坚持没有被好好留存，只有比赛名次。
5. **有门槛**：有天赋但家境困难的孩子，缺装备、名额和指导。

## 3. 产品原则

- **安全 > 增长**：未成年人产品，安全是第一条产品需求，不是合规附属品。
- **成长 > 竞速**：记录每一次坚持，不用名次定义孩子。
- **真实 > 热闹**：只认有证据的成绩；宁可榜单小，不要数据假。
- **供给先行**：先让跑团用起来，再让个人用户进来。
- **小切口**：一个城市、几个跑团、几百个孩子，跑通再复制。
- **公益底色**：早期不靠抽成、广告和现金捐赠赚钱。

## 4. 六大功能：分三层做

| 层级 | 功能 | 它在系统里的作用 | 建议阶段 |
|---|---|---|---|
| 地基 | 全国跑团登记入驻 | 供给网络；没有跑团，后面都是空转 | 第 1 版 |
| 地基 | 跑步记录与成长档案 | 数据底座；没有真实数据，榜单和匹配都是假的 | 第 1 版 |
| 连接 | 业余成长排名体系 | 留存与荣誉；但必须改造“竞速榜” | 第 1 版做轻量版 |
| 连接 | 大数据跑友匹配 | 同城与同水平连接；先做活动，不做陌生人私聊 | 第 2 版 |
| 连接 | AI 长跑经验数据库 | 内容与信任；先人工精选，再 AI 检索 | 第 2 版 |
| 旗舰 | 金字传驿跨年接力 | 品牌旗舰；需要足够的跑团和运营能力 | 第 3 版 |
| 旗舰 | 公益助跑帮扶 | 社会价值；必须与有资质的公益伙伴合作 | 第 3 版 |

### 4.1 跑团入驻（第 1 版）

第一版只做：申请、审核、跑团主页、成员列表、活动发布、加入申请。
第二版再加：跨团资源共享、教练入驻、跑团等级与认证、区域联赛。
关键设计：每个跑团必须有一个真实负责人；平台管理员人工审核；跑团可设置“是否接受未成年人加入”和“是否需要监护人确认”。

### 4.2 成长排名（第 1 版做轻量版）

原始设想是“区/市/省/全国四级榜单、男女分组、1500 米到全马”。这个方向有品牌价值，但直接做会带来三个问题：未成年人过度训练、身材焦虑、成绩作弊；而且“拒绝内卷”和“排行榜”天然矛盾。

建议改造成 **“成长档案 + 团队成长榜”**：

- 个人侧：记录 PB、月跑量、连续周数、参赛经历、徽章；默认仅自己可见。
- 团队侧：展示跑团参与度、总里程、进步幅度、完赛人数；不展示个人绝对速度排名。
- 年龄分级：用年龄系数折算，避免 10 岁和 20 岁直接比。
- 成绩分级：手动记录、活动认证、赛事成绩三种可信度；榜单只认后两种。
- 激励：证书、徽章、抽签名额、装备；不发大额现金。

等用户量和数据质量起来后，再开放“可选公开”的个人榜，且 18 岁以下默认匿名。

### 4.3 金字传驿（第 3 版）

这是最有记忆点的品牌赛事，但也是最重的运营项目。建议在第一年只做“一省试点”，第二年再扩。

- 赛制：每省 10 支跑团，每队 100 公里接力；跨年档期；团队总成绩 + 个人分段成绩，娱乐化排名。
- 必备：保险、赛事备案/报批、急救、补给、直播/轨迹、反作弊、天气预案。
- 第一版不做实时轨迹和全国直播，先做“线下接力 + 线上成绩上传”。

### 4.4 AI 长跑经验数据库（第 2 版）

先做“精选内容库 + 教练问答”，再做 AI。

- 内容分类：训练计划、伤病康复、比赛经验、装备、心理、营养。
- 每篇内容有作者、审核人、更新时间；医疗类内容必须标注“不能替代医生诊断”。
- AI 只做检索和总结，引用来源；不直接给诊断和处方。
- 教练回答要可追溯；建立举报和下架机制。

### 4.5 跑友匹配（第 2 版）

未成年人安全优先，第一版不做 1 对 1 陌生人匹配。

- 先做“同城跑团 + 同城活动”匹配：按城市、年龄段、配速区间推荐跑团和活动。
- 1 对 1 匹配必须：监护人同意、实名/年龄校验、只在公开场所、不显示精确位置、不开未成年人私信。
- 匹配维度：城市、年龄、配速、周跑量、目标赛事；不做“颜值/身材”维度。

### 4.6 公益助跑（第 3 版）

这是最需要克制的一块。

- 公开募捐需要资质；个人和普通公司不能随意向公众收钱。
- 第一版只做“物资/名额/教练时间”的定向匹配，不碰现金。
- 与有公募资格的基金会/慈善组织合作；善款进对公账户；受助人隐私保护；定期公示。
- 受助对象审核：家庭情况、教练推荐、学校/社区证明；避免“卖惨”叙事。

## 5. 第一版（MVP）范围

### 做

1. 跑团入驻与审核（跑团主页、成员、加入申请）。
2. 活动发布与报名（含监护人同意、风险告知）。
3. 跑步记录（手动录入 + 计时；GPS 放第二版）。
4. 个人成长档案（PB、月跑量、连续周数、徽章）。
5. 俱乐部成长榜（参与度、进步、坚持；不公开绝对速度）。
6. 经验库（20–30 篇精选 + 教练问答，人工审核）。
7. 隐私设置、举报、后台审核。

### 不做

- 全国四级榜单
- AI 问答
- 1 对 1 跑友匹配
- 现金捐赠
- 跨省接力
- 实时 GPS 轨迹
- 公开社交动态/私信
- 付费会员

### 试点目标

- 1 个城市
- 5–10 个跑团
- 300 名 10–20 岁青少年
- 1 场线下活动
- 4 周跑通“入驻 → 报名 → 记录 → 成长档案”闭环

## 6. 关键流程

1. **跑团入驻**：提交资料 → 平台审核 → 开通主页 → 邀请成员。
2. **青少年注册**：手机号/微信登录 → 填写年龄 → 未满 18 岁进入监护人同意 → 选择跑团 → 设置隐私。
3. **活动报名**：跑团发布 → 跑者报名 → 监护人确认/风险告知 → 签到 → 活动记录。
4. **跑步记录**：手动/计时 → 保存 → 进入成长档案 → 计入跑团成长值。
5. **内容发布**：投稿 → 审核 → 发布 → 举报/下架。

## 7. 数据模型（概念版）

- users：id、角色、出生日期、性别、城市、学校（可选）、监护人同意状态、隐私设置。
- clubs：id、名称、城市、类型、负责人、认证状态、简介、logo。
- club_members：user_id、club_id、角色、状态。
- events：id、club_id、标题、类型、时间、地点、人数上限、是否需监护人同意。
- event_signups：event_id、user_id、监护人同意时间、状态。
- run_logs：id、user_id、日期、距离、时长、来源（手动/活动/赛事）、可信度、活动 id。
- personal_bests：user_id、项目、成绩、日期、赛事、认证状态。
- articles：id、作者、分类、标题、正文、审核状态、审核人。
- coach_questions：id、提问者、问题、回答教练、状态。
- reports：id、举报对象、原因、处理状态。

第一版可以用 Supabase 的 Postgres + Row Level Security 快速实现；正式上线前再评估境内合规云。

## 8. 合规与安全清单

| 事项 | 要求 | 第一版怎么做 |
|---|---|---|
| 未成年人个人信息 | 监护人同意；最小化收集；敏感信息单独同意 | 注册时年龄分流；<18 岁监护人确认；不收集学校/位置除非必要 |
| 位置安全 | 不公开精确位置；线下活动在公开场所 | 只显示城市/区；活动地点报名后可见 |
| 社交安全 | 防骚扰、防陌生人约见 | 18 岁以下不开私信；举报/拉黑；活动由认证跑团组织 |
| 内容合规 | UGC 审核、医疗免责声明 | 先审后发；医疗内容人工审核；AI 不诊断 |
| 公益募捐 | 公开募捐资质；善款公示 | 第一版不收现金；与基金会合作 |
| 赛事安全 | 保险、急救、报批、风险告知 | 试点活动买保险；签风险告知；设急救预案 |
| App/小程序备案 | ICP/APP 备案、隐私政策、权限说明 | 上线前办理；原型阶段用测试数据 |
| 数据真实性 | 反作弊、成绩认证 | 区分记录来源；榜单只认认证成绩 |

## 9. 技术方案

### 建议的第一版组合

- 客户端：Expo（React Native）+ TypeScript + Expo Router
- 后端：Supabase（Auth + Postgres + Storage）
- 状态与请求：React Query
- 地图/定位：第二版再接（高德/腾讯位置服务）
- 推送：第二版再接（Expo Notifications）
- 管理后台：第一版用 Supabase 控制台 + 简单网页；第二版做独立后台

### 为什么

- 一套代码出 iOS/Android；用 Expo Go 当天就能在手机上看到。
- 不需要先买服务器；Supabase 免费额度够试点。
- 后面接定位、推送、健康数据都有成熟方案。
- 等验证后，再补微信小程序做传播渠道。

### 成本预估（试点）

- Expo/EAS：免费额度可起步
- Supabase：免费额度可起步
- Apple Developer：如要装到 iPhone 真机/TestFlight，约 99 美元/年
- 域名/备案/保险/活动物料：按实际情况
- 第一版总现金投入建议控制在 0–3000 元，先把闭环跑通

### 正式上线前要补的

- 境内合规云与数据存储
- 隐私政策、用户协议、未成年人保护规则
- APP 备案/ICP、应用商店资质（软著等）
- 内容审核与客服
- 等保/安全评估（视规模）

## 11. 成功指标

- 北极星指标：**每周至少记录 1 次跑步的青少年数**（Weekly Active Runners）。
- 供给：认证跑团数、月活跑团管理员数、每月活动数。
- 需求：注册青少年数、周活跃率、人均周跑量、活动报名率。
- 留存：4 周留存、跑团留存、活动复参率。
- 安全：监护人同意率、举报处理时长、活动事故数（目标 0）。
- 内容：文章阅读量、问题回答率、教练响应时长。
