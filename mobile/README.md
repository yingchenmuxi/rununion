# 青跑团 mobile

青跑团手机端，Expo SDK 58 + React Native + Expo Router。一套代码可跑 Android、iOS 和 Web。

当前是**可点击原型**：不接真实后端，不录入真实未成年人信息。记录和知识库仍用内存演示数据；活动、报名、出勤、站内消息、跑团公告、成员名册和入团申请由本地 Mock API 提供，和社团后台共用同一份数据。记录支持 GPS 前台计距离、截屏人工确认、GPX/TCX/CSV 文件导入；不保存轨迹、不上传地图。另有 9 篇本地跑步知识文章，支持搜索、主题筛选、收藏和关联阅读；4 场演示活动支持报名、待确认、取消、已参加、未到和我的活动。跑团页可进入跑团主页，公告支持全部 / 未读筛选和详情已读；消息中心支持未读筛选和跳转活动；成长页沉淀活动参与；公益助跑可查看透明账本（示例数据）。入团申请提交后每 2.5 秒检查审批结果，后台通过后自动进入欢迎页，拒绝时显示社长留言并支持预填资料重新申请；入团表单不再收集密码。

## 运行

先在项目根启动共享活动数据：

```bash
cd ..
node mock-api/server.mjs
```

再回到 `mobile` 启动 Expo：

```bash
npm install
npm run web
```

静态导出与本地预览：

```bash
npm run web:export
npm run preview:web
```

`preview:web` 会同时启动 Mock API 和静态文件服务，地址为 <http://127.0.0.1:8090>。服务带 SPA fallback，直接访问 `/school`、`/run`、`/growth`、`/profile`、`/knowledge`、`/knowledge/knee`、`/activities`、`/my-activities`、`/activity/act-001`、`/club`、`/announcements`、`/announcements/ann-001` 不会 404。

真机预览：安装 Expo Go，电脑和手机连同一 Wi-Fi，在 mobile 目录运行 `npm start`，扫描二维码。局域网不通时用 `npx expo start --tunnel`。

## 目录

```
src/
├─ app/                 页面与 Expo Router 路由
├─ components/          共享 UI、底栏
├─ constants/           颜色、间距、演示数据
├─ features/
│  ├─ auth/             登录、邀请码、待审批
│  ├─ runs/             共享记录、GPS 距离、文件解析、导入卡片
│  ├─ knowledge/        本地文章、收藏状态
│  ├─ activities/       活动数据、共享报名状态
│  ├─ announcements/    跑团公告、已读状态、共享接口
│  ├─ notifications/    站内消息、未读数
│  └─ charity/          公益账本示例数据
└─ ...
```

`ActivityProvider`、`NotificationProvider`、`AnnouncementProvider`、`KnowledgeProvider` 和 `RunProvider` 在 `src/app/_layout.tsx` 中依次包住页面树。活动 Provider 通过 `activityApi.ts` 读写 8090 的共享 Mock API；首页、跑团、活动列表、详情和我的活动共用同一份报名和出勤。消息 Provider 通过 `notificationApi.ts` 读取站内消息，首页铃铛、消息中心和我的页共用同一份未读数；公告 Provider 通过 `announcementApi.ts` 读取已发布公告和已读状态，跑团页、跑团主页、公告列表和详情共用同一份数据。消息页、公告页、活动详情和首页在获得焦点时会刷新，后台刚改完也能看到。首页、开跑、成长、我的读取同一份记录；知识库列表、详情和我的页共用同一份收藏。

## 检查命令

```bash
npm run typecheck
node scripts/probe-direct.mjs
node scripts/shot-tabs.mjs
node scripts/e2e-auth.mjs
node verify-run-sync.mjs
node verify-three-channels.mjs
node verify-knowledge.mjs
node verify-activities.mjs
node verify-messages.mjs
node verify-announcements.mjs
cd .. && node verify-membership.mjs
```

- `probe-direct`：检查五个直链是否渲染、是否有 console 错误。
- `shot-tabs`：按 390×844 截五页图。
- `e2e-auth`：用本地 CDP 无头 Edge 跑登录、错误/正确邀请码、无密码入团资料、提交待审批和退出登录，截 3 张图；不需要 Playwright。
- `verify-run-sync`：手动记录、计时记录、首页 / 成长 / 我的同步，并截取本轮证据图。
- `verify-three-channels`：模拟 GPS、选择真实截图、导入 CSV，检查三通道保存和同步；GPX/TCX 解析器另有单元测试。
- `verify-knowledge`：检查列表、搜索、空状态、主题筛选、收藏、详情、关联阅读和我的页收藏篇数。
- `verify-activities`：64 项共享/跨端检查：重置种子、首页、四筛选、详情、我的活动、取消、后台改未到后的手机端同步、撤销签到、重置；需要 8090 的 Mock API，截 17 张图。
- `verify-messages`：53 项消息、成长、公益检查：铃铛未读、未读筛选、全部已读、消息跳活动、后台改期后的变更消息、活动参与、公益账本和重置；需要 8090 的 Mock API，截 12 张图。
- `verify-announcements`：49 项跑团公告与跑团主页检查：跑团页公告、跑团主页、全部 / 未读筛选、详情已读、发布后的公告消息、撤回清理和恢复种子；需要 8090 的 Mock API，截 9 张图。
- `verify-membership`（项目根）：58 项手机 + 后台跨端检查：邀请码、无密码表单、提交申请、后台通过、手机端自动进团、拒绝原因、预填重提；需要 8090 和 5173 都在运行，截 9 张手机图。

## 边界

- 记录只在内存中，刷新恢复演示数据。
- 活动和公告、报名与已读状态存在 Mock API 的进程内存里，刷新保留，重启服务或重置回种子；没有真实团长审批、监护人授权、真实推送或候补。
- 入团申请、审批结果和成员名册也存在 Mock API 内存；刷新网页回登录页，没有真实账号、密码或会话持久化。新成员进团后仍使用演示成员 `m-001` 的活动、消息和成长数据。
- 站内消息和公告只是进入页面或重新获得焦点时拉取，不轮询；后台改完后重新进入消息页、公告页、活动详情或首页才会看到，停留页不动不会自动更新。
- 公告不能带图片、附件或富文本；已读数只统计演示成员打开详情，没有已读回执。跑团主页的成员数、本周公里和安全约定仍是静态演示数据。
- 手机端与社团后台活动数据已互通；消息也随活动重置一起回到种子。
- 公益账本是写死的示例数据，不接捐赠、支付、库存或受助人档案，也没有后台维护界面。
- 签到是团长手工记录，不是到场验证。
- GPS 只在前台累计距离，不保存轨迹；真实设备上的精度、耗电和锁屏行为尚未验证。
- 截图通道不自动 OCR，保存前必须人工确认数字；文件通道暂不支持 FIT。
- 手机端、社团后台、平台总后台的其他演示数据仍互不相通；只有活动和公告模块共用 Mock API。
- 知识库是 9 篇本地演示稿，没有作者署名、外部来源或医学审核，不能当作正式科普或医疗建议。
- 收藏只在内存中，刷新恢复初始 3 篇；没有阅读历史、分享或评论。
- 个人最好、徽章、团队榜、跑团本周里程和跑团主页的成员数仍为静态演示数据。
